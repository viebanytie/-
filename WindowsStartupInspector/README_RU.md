# Windows Startup Inspector 1.0.0

Простая текстовая программа на Python для Windows 10/11. При запуске открываются два отдельных окна: автозапуск программ и все службы, включая остановленные, отключённые службы и драйверы. Списки можно искать, сортировать по заголовкам, фильтровать и экспортировать в CSV для Excel. У каждой записи есть подробности и поле собственного комментария.

## Запуск и сборка через CMD

1. Установите **Python 3.12 x64** с python.org. Оставьте компоненты **Tcl/Tk** и **Python Launcher** включёнными.
2. Распакуйте весь ZIP в обычную папку, например `C:\Tools\WindowsStartupInspector`. Не запускайте CMD внутри открытого ZIP.
3. Откройте `START.cmd` для запуска исходников. Сторонние Python-библиотеки для работы программы не нужны.
4. Для получения одного EXE откройте `BUILD.cmd`, либо выполните в CMD:

   ```cmd
   cd /d C:\Tools\WindowsStartupInspector
   BUILD.cmd -Clean
   ```

   Сборщик создаёт `.venv-build`, устанавливает фиксированные версии зависимостей из `requirements-build.txt`, запускает тесты и собирает `dist\WindowsStartupInspector.exe`. Для первой сборки нужен Интернет: `pypi.org` и `files.pythonhosted.org`. Проверка TLS не отключается. CMD сохраняет код ошибки сборки.

5. Готовый EXE можно перенести на Windows-компьютер без Python. Windows PowerShell 5.1, WMI/CIM и планировщик заданий должны быть доступны: это штатные компоненты Windows 10. EXE собирается на Windows, не на Linux.

Для чтения максимально доступных данных запустите `START.cmd` или собранный EXE **от имени администратора**. Программа сама не запрашивает повышение прав и работает с обычными правами, показывая ошибки доступа. Корпоративная политика может запрещать PowerShell; программа покажет соответствующую ошибку. Все действия программы по отношению к Windows — чтение: она не включает и не отключает автозапуск и службы.

## Что отображается

Автозапуск:

- Run, RunOnce и Policies\Explorer\Run в 32- и 64-битном реестре: компьютер и **уже загруженные** пользовательские ветки HKU.
- Доступные папки Startup всех обнаруженных профилей, общая папка Startup и перенаправленные папки загруженных профилей. Для ярлыков показываются цель, аргументы и рабочая папка.
- Отметки StartupApproved: отключённые записи остаются видимыми. «Нет отметки отключения» означает отсутствие известного флага, а не доказанный факт запуска процесса.
- Задания планировщика с триггером загрузки или входа, включая отключённые задания. Другие условия задания могут препятствовать запуску.
- Shell/Userinit Winlogon и BootExecute.

Это обзор основных источников автозапуска, а не полный аналог Sysinternals Autoruns. Незагруженные пользовательские файлы NTUSER.DAT не монтируются; расширения оболочки, AppInit_DLLs, WMI event consumers и все остальные специальные механизмы здесь не перечисляются. Список — снимок настроек, а не журнал уже запущенных процессов. Реально работающие службы видны по состоянию «Работает».

Службы:

- **Все записи, которые Windows возвращает через Win32_Service и Win32_SystemDriver**, без фильтра по состоянию или типу запуска. По умолчанию включены драйверы и отключённые службы.
- Отображаемое и системное имя, описание Windows, состояние, тип запуска, учётная запись, команда/путь, тип службы и код выхода.
- Отложенный автоматический запуск, зарегистрированные зависимости и число триггеров из реестра, если доступны.
- При отсутствии системного описания используется описание файла; если нет и его, это явно указано. Универсальные советы о безопасности отключения конкретных служб программа не выдумывает.

Кнопка **«Ошибки / полнота списка»** показывает источники и ошибки чтения. При недоступности WMI, планировщика, реестра или чужих папок нельзя считать снимок полным. Даже запущенная служба с ручным типом запуска может работать благодаря триггеру или запросу другой программы. Тип «Автоматически» сам по себе не доказывает, что служба успешно запустилась.

## Комментарии и экспорт

Выберите запись, введите заметку и нажмите **«Сохранить комментарий»**. Заметки находятся в `%LOCALAPPDATA%\WindowsStartupInspector\comments.json` и восстанавливаются при следующих запусках. Пустой комментарий удаляет заметку. Изменения в поле нужно сохранить до выбора другой записи. Повреждённый файл заметок не перезаписывается.

CSV содержит **текущий отфильтрованный список** вместе с описаниями, путями, подробностями и вашими сохранёнными заметками. Кодировка UTF-8 с BOM, разделитель `;`. Поиск учитывает также путь, подробности и сохранённые комментарии.

`F5` обновляет текущее окно, `Ctrl+F` ставит курсор в поиск. Закрытие окна служб скрывает его: используйте «Открыть другое окно». Закрытие основного окна автозапуска или кнопка «Выход» закрывает всю программу.

## Проверка и диагностика

```cmd
py -3.12 -m unittest discover -s tests -v
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tests\check_powershell.ps1
py -3.12 startup_inspector.py --dump startup > startup.json
py -3.12 startup_inspector.py --dump services > services.json
py -3.12 startup_inspector.py --demo
```

`--demo` показывает **вымышленные** записи и явно помечает оба окна. Это проверка интерфейса, а не инвентаризация компьютера. JSON-команды завершаются с ненулевым кодом при сбое процесса чтения; частичная инвентаризация содержит `warnings`, которые также надо проверить.

Для разработки на Linux: Python 3.12 с Tk, `python3 -m unittest discover -s tests -v`; просмотр интерфейса — `python3 startup_inspector.py --demo`. Сборка и реальная инвентаризация Windows требуют Windows 10/11. Дополнительная проверка GUI: `python3 tests/gui_smoke.py` при доступном дисплее.

При чтении выполняется локальный `inspect_windows.ps1`. Программа не отправляет сведения об автозапуске, службах или ваши заметки в сеть. ZIP содержит исходники, тесты и сборщик; готового Windows EXE в исходном архиве нет.
